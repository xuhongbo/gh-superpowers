# 一期失败场景说明

本文档描述一期系统在各类异常情况下的行为。

## 1. 未绑定 Issue 时执行操作

**触发**：在未绑定 Issue 的情况下调用 `sync-ledger`、`publish-plan` 等动作。

**预期行为**：抛出错误 `当前还没有绑定 Issue`。

**恢复**：先执行 `bind-issue` 绑定到目标 Issue。

## 2. Plan 版本不存在

**触发**：调用 `publish-plan` 时指定的 `planVersion` 在 GitHub 上找不到对应的托管评论。

**预期行为**：如果 `payload.planText` 存在，使用传入的 plan 文本；否则尝试从已发布的 plan 评论中查找。如果都找不到，抛出 `找不到当前 plan 评论`。

**恢复**：传入 `planText` 参数或先发布 plan。

## 3. PR 关联失败（MCP 通道）

**触发**：MCP 通道调用 GitHub search API 失败（网络问题、权限不足）。

**预期行为**：抛出 MCP 请求失败错误，`sync-ledger` 中断。

**恢复**：检查 MCP 认证状态，或切换到 gh CLI 通道。

## 4. PR 关联失败（gh 通道）

**触发**：`gh issue view` 命令失败（未认证、Issue 不存在）。

**预期行为**：抛出 `gh command failed` 错误。

**恢复**：运行 `gh auth login`，确认 Issue 编号正确。

## 5. 必需 Check 持续失败

**触发**：`requiredChecks` 中定义的某个 check 持续失败（非 `success` 状态）。

**预期行为**：相关任务被标记为 `blocked` 状态，账本中出现偏差告警。

**恢复**：修复 CI 问题使 check 通过，或人工解除阻塞。

## 6. 阻断性 Review

**触发**：PR 上存在 `CHANGES_REQUESTED` / `REQUEST_CHANGES` / `BLOCKED` 状态的 review。

**预期行为**：被关联的任务被标记为 `blocked`，描述为 review 内容或 `review blocked`。

**恢复**：解决 review 意见后重新提交 review。

## 7. 新旧 Plan 版本 Task 对不上

**触发**：重新发布 plan 后，Task 列表与之前版本不一致。

**预期行为**：账本偏差告警中显示新增和移除的 Task ID。

**恢复**：人工确认变更是否预期，必要时调整 plan 或 Task 绑定。

## 8. 有 Task 无事实

**触发**：Task 被抽取后，没有任何 PR、commit、check、review 与之关联。

**预期行为**：状态保持 `todo`，账本中显示 `有任务暂无事实：T5` 类偏差。

**恢复**：在 PR body 或 commit message 中添加 `task-links` 绑定块。

## 9. 有事实无 Task

**触发**：PR/commit 中绑定了不存在的 Task ID（拼写错误或 plan 已变更）。

**预期行为**：该事实被记录为 `orphanFacts`，账本中显示 `存在事实未归档到任务：T99` 偏差。

**恢复**：修正 Task ID 或更新 plan。

## 10. 阻塞后主线仍错误推进

**触发**：Task 被标记为 `blocked` 后，仍有新的 PR/commit 绑定到该 Task。

**预期行为**：账本中显示 `阻塞后仍有事实推进：T2` 偏差，但状态仍保持 `blocked`。

**恢复**：人工确认是否需要解除阻塞或丢弃该 Task。

## 11. 已实现未验证

**触发**：Task 有实现事实（PR/commit），但必需 check 未全部通过。

**预期行为**：状态为 `implemented`，账本中显示 `已实现但未验证：T3` 偏差。

**恢复**：修复 failing check，重新跑 CI。

## 12. 已验证未验收

**触发**：Task 已通过所有必需 check，但无人工验收动作。

**预期行为**：状态为 `verified`，账本中显示 `已验证但未验收：T6` 偏差。

**恢复**：人工执行 `accept-task`。

## 13. repository 配置缺失

**触发**：业务仓中 `gh-superpowers.config.json` 不存在或 `repository` 字段为空。

**预期行为**：使用默认配置（repository 为空字符串），在需要 repository 的操作时抛出 `repository 配置缺失或无效`。

**恢复**：在业务仓根目录创建 `gh-superpowers.config.json` 并填写 `repository`。
